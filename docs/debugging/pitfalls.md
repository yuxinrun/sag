# 故障排查清单

SAG 出问题时，症状往往都长得像「模型答错了」。先把问题归到八段管线里的某一段，再动手改；否则你会花半天调提示词，最后发现是抽取没跑。

> **先定位阶段，再改代码。** 一条 trace 应该能告诉你是分块、抽取、召回、JOIN、剪枝、重排还是引用组装出了问题。

## 八类故障速查

| 症状 | 优先检查 | 常见原因 | 修复 |
| --- | --- | --- | --- |
| 跨文档链路断 | `event_count`、`chain_hit` | `extract()` 没跑完 / 实体抽取漏了共享词 | 补跑抽取，检查实体类别与别名归一 |
| 答案缺关键事实 | `recall@2`、种子集合 | 只用了语义一路，专名漏召回 | 打开词法 / BM25 双路召回 |
| 结果里全是泛化实体 | frontier 候选数 | 「公司」「2024」等高频共享实体扇出 | 降权高频实体、收紧 `frontier_cap` |
| 答案对但引用错 | `citation_valid`、去重逻辑 | 按文本相似度去重、`chunk_id` 不稳定 | 按 `chunk_id` 去重，编号确定性生成 |
| 请求变慢 / 超时 | p95、`llm_calls`、精排阶段 | `top_k` 过大、精排串行、高频实体扇出 | 先收窄 `source_ids`，再换 `multi_es_fast` |
| 数据更新后答案仍旧 | `embedding_model`、缓存键 | 换模型未重建索引 / 缓存未失效 | 重建索引、清空相关缓存 |
| 出现别的信源内容 | `source_ids`、MCP URL | MCP 省略 `source_id` 连接全库 | 按 Agent 签发带 `source_id` 的 URL |
| 空结果被硬编成答案 | `refusal_correctness` | 种子为空后无限放宽 | 空结果直接结束，明确拒答 |

## 排查顺序

1. **看降级标记**：`truncated` / `degrade` / `strategy`，确认这不是一个「正常的降级答案」。
2. **看索引是否完整**：`chunk_count` 与 `event_count` 是否匹配。大量 chunk 没有 event，基本可定位到抽取阶段。
3. **看种子**：种子实体 / 事件是否包含问题里的关键专名。没有就是双路召回的问题。
4. **看逐跳**：每跳候选数与共享实体分布，哪一跳断了 → JOIN 或预算。
5. **看候选与重排**：结构候选与直召 chunk 是否被正确融合、去重。
6. **看上下文包**：`chunk_ids`、`top_k`、tokens、是否只含原文。
7. **看验证结果**：引用存在性、支撑性、是否触发回查。
8. **最后才看模型输出**。绝大多数「模型不行」其实是证据没给对。

## 三个典型走查

### 场景一：「跨文档问题答不上来」

1. 检查抽取任务状态：`extract()` 是否完成，是否有 chunk 被跳过。
2. 在关系表里查两个文档的事件是否真的共享某个实体；没有共享实体，JOIN 无从扩展。
3. 判断是否抽取漏了别名（「Atlas 网关」vs「Atlas Gateway」）——官方只做同 source 内同类型同名复用，跨 source 别名需要你自己的治理。
4. 把该问题加进回归集，门禁设为结构路径命中率不下降。

### 场景二：「p95 从 300ms 涨到 4s」

1. 按共享实体分组看候选数，找出高频实体热点。
2. 看 `top_k` 是否被当成「提升质量」的手段一路调大——官方明确不建议。
3. 看 LLM 精排是否串行、JEV 是否超时回退。
4. 加 `frontier_cap` 与请求超时，必要时切 `multi_es_fast`，并把降级写进 trace。

### 场景三：「改了 embedding 后效果全面下降」

1. 确认旧索引是否重建；换模型后向量不可比是必然结果。
2. 确认同一进程内没有混用两份 `EngineConfig`（官方说明连接是进程级全局资源）。
3. 确认 `SAG_EMBEDDING_MODEL` 与索引时一致；官方 README 特别提示升级已有 BGE 索引时要保留该配置。
4. 用同一套回归集重跑，而不是拿新数字去和论文表格比。

## 上线前检查清单

- [ ] `ingest` 与 `extract` 都有任务状态与失败重试，抽取失败时原文仍可用
- [ ] 双路召回都开启，专名 / 编号有词法兜底
- [ ] 跳数、`frontier_cap`、`top_k` 三类预算均有触顶语义与降级措辞
- [ ] 融合按 `chunk_id` 去重，引用编号确定性生成
- [ ] `citation_valid` 设为发布硬门禁
- [ ] trace 覆盖策略、种子、逐跳候选、`chunk_ids`、耗时与 token
- [ ] 回归集含单跳、组合式多跳、专名、空结果、预算边界、对抗样例
- [ ] 降级路径与缓存命中也计入指标与告警
- [ ] MCP 连接按 Agent 收窄到 `source_id`，token 未进仓库与日志
- [ ] 生产认证、HTTPS、SSE、`pgdata` + `sagdata` 备份按 [官方清单](/engineering/production) 验收

::: tip 每次事故复盘都问一句
「这条 trace 能不能让我在不重跑模型的情况下，看出是哪一块原文证据没被取回？」不能，就先补观测，再补功能。
:::
